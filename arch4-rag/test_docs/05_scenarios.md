# 아키텍처 운영 시나리오

## 시나리오 1: 최근 5분간 이벤트 검색
운영자가 최근 5분 동안 발생한 특정 이벤트를 빠르게 검색하려고 한다.

권장 경로는 OpenSearch이다.

이유는 OpenSearch가 실시간 검색과 분석에 적합하기 때문이다.

## 시나리오 2: 지난 1년간 전체 이벤트 분석
분석가가 지난 1년간의 전체 이벤트 데이터를 대상으로 SQL 분석을 수행하려고 한다.

권장 경로는 S3 + Glue + Athena이다.

S3에 저장된 Raw Data를 Glue Data Catalog로 정의하고 Athena에서 SQL을 실행한다.

## 시나리오 3: 원천 데이터 보관
규정이나 재처리를 위해 원천 이벤트를 장기간 보관해야 한다.

S3가 적합하다.

## 시나리오 4: 실시간 대시보드
최근 이벤트 발생량이나 이벤트 유형을 실시간으로 확인하는 대시보드를 만들려고 한다.

OpenSearch에 이벤트를 전달하고 OpenSearch 기반 검색/집계를 사용하는 구성이 적합하다.

## 시나리오 5: 새로운 분석용 테이블 추가
S3에 새로운 형태의 이벤트 데이터가 추가되었다.

Athena에서 SQL로 조회하려면 해당 데이터의 구조와 S3 위치를 Glue Table 등의 메타데이터로 등록해야 한다.

## 시나리오 6: Athena가 데이터를 저장하는가?
아니다.

Athena는 쿼리 엔진이며, 이 아키텍처에서는 S3에 저장된 데이터를 SQL로 조회한다.
